# Artifacts (shared pages)

Results are read visually and shared with the team, so they go on a page, not only in the terminal.

- **Real examples, not invented numbers.** Every example runs on real data. For agent capabilities: a chat mockup in the app's own style, beside it the method, the numbers, the caveats and what an expert must decide.
- **Many charts.** A chart next to every measured result, a table under each chart, selectors to switch entity or measure. Render-check light, dark and phone width.
- **Always several versions.** Proposals (visual, UX, wording) come as 2–4 versions side by side, each with its one-line trade-off.
- **UX options as mockups.** When a UX choice is the human's, draw the options side by side; then build exactly the one picked.
- **Living plan.** A fix list/plan page is updated after each item: status, diff, checks, how to verify, next step. Delete options once discarded; keep a comparison only where it is the reason for the current choice.
- **Specs for other owners.** Work in a service you don't own becomes a spec page for its owner: evidence (file:line), fix, tests, rollout, status column; recheck against their main before adding.
- **Reader's voice.** Client release notes: short one-liners per visible change, no internals. Reports in the reader's language; technical names only when the reader is technical.
